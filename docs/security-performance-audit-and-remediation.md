# 历史记录：安全、稳定性与性能审计

审计日期：2026-08-22（Asia/Shanghai）

以下是当时的审计与修复记录，表中问题已完成修复。当前版本验证见 [写作体验验收](writing-experience-acceptance.md)，构建环境以 [贡献指南](../CONTRIBUTING.md) 为准。

## 范围与基线

本审计覆盖 Go 后端、Wails API、本地 Markdown/附件存储、索引与 watcher、更新与导出流程、前端 Markdown/DOM 渲染、构建与测试工具链。审计遵循“代码路径 + 现有测试 + 构建门禁”三重验证；只把能够由当前代码复现或明确推导的问题列为待修复项。

工作区基线：

- `go test -count=1 ./...`：通过（非缓存全量回归；`internal/index` 规模测试约 336 秒）。
- `go vet ./...`：通过。
- `npx tsc --noEmit`：通过。
- 默认 `npm test -- --run`：失败，Vitest 8 个 worker 在当前 Windows 中文路径环境下等待响应超时，未执行测试用例；需要单进程/低并发验证并修复测试配置。
- `docs/qiaoji-core-optimization-baseline.md` 中记录的既有优化作为背景输入，不覆盖或回滚用户已有改动。

## 风险清单

| 编号 | 严重度 | 问题 | 影响 | 阶段 | 状态 |
| --- | --- | --- | --- | --- | --- |
| S-01 | 高 | Vault 只做词法路径包含判断，未统一解析符号链接；部分读写、删除、文件夹操作还允许访问 `.qiaoji` 内部目录 | 符号链接可把读写、移动、恢复和附件操作导向 vault 外部；内部索引/标记文件可被 API 当作笔记修改 | 1 | 已修复 |
| S-02 | 高 | 回收站跨卷复制会跟随符号链接，且恢复/移动缺少统一的目标边界校验 | 可能把 vault 外部内容复制进回收站，或在异常路径下造成数据丢失/泄露 | 1 | 已修复 |
| S-03 | 高 | Windows 更新辅助脚本通过 `cmd.exe /C` 拼接安装目录参数 | 安装目录含 shell 元字符时存在命令注入/错误安装风险 | 1 | 已修复 |
| S-04 | 中 | Wails API 的旧列表接口、搜索查询、游标和标签/标题输入缺少统一大小上限 | 恶意或损坏笔记可导致内存、SQLite FTS/LIKE 和 UI 响应被拖垮 | 1 | 已修复 |
| S-05 | 中 | `SaveNote`/附件等失败路径提前写入 self-write 标记 | 失败请求后的外部变更可能被 watcher 暂时忽略，造成索引滞后 | 1 | 已修复 |
| S-06 | 中 | `OpenVault` 切换成功后再保存设置，设置持久化失败会导致当前 vault 与下次启动 vault 不一致 | 重启后打开错误笔记库，用户感知为数据“消失” | 1 | 已修复 |
| F-01 | 中 | PDF `fileURL` 仅转义空格，没有正确编码 `#`、`?`、`%`、Unicode 等路径字符 | 特殊目录/文件名导出 PDF 失败或读取错误文件 | 2 | 已修复 |
| F-02 | 中 | 导出文件名未处理 Windows 保留设备名（如 `CON.md`） | 导出失败或被 Windows 特殊设备语义截获 | 2 | 已修复 |
| F-03 | 中 | DOCX/HTML/PDF 直接写目标文件，失败时可能留下半成品 | 用户得到损坏或不完整的导出文件 | 2 | 已修复 |
| F-04 | 低 | `OpenExternal` 只做大小写敏感前缀判断 | 控制字符、空 host、凭据或异常 URL 可能交给系统浏览器 | 2 | 已修复 |
| F-05 | 低 | 搜索结果高亮在 fallback 分支直接写入 `innerHTML` | 后端异常/旧数据返回空高亮时，标题文本可能被当作 HTML 解释 | 3 | 已修复 |
| F-06 | 低 | Markdown 预览拦截了所有链接，但只处理外链和锚点 | 相对 Markdown 笔记链接点击后无动作 | 3 | 已修复 |
| T-01 | 中 | Vitest 默认 fork 并发在 Windows 中文路径下 worker 启动超时 | CI/本机无法稳定执行前端回归测试 | 3 | 已修复 |
| P-01 | 中 | 索引查询与同步对异常大 Markdown、搜索词和标签缺少预算 | 冷启动、同步和搜索峰值内存/耗时不可控 | 1 | 已修复 |
| S-07 | 中 | 笔记大小只在 body 层校验，序列化 front matter 后可能超过文件预算并留下已写入文件 | API 返回失败但磁盘内容已改变，索引与编辑器状态不一致 | 1 | 已修复 |
| S-08 | 中 | 批量标签操作复用有界列表接口，超过一批后会静默漏改笔记 | 用户以为标签已全部重命名/删除，实际留下部分旧标签 | 1 | 已修复 |
| S-09 | 中 | 跨卷复制 fallback 未拒绝目标链路中的符号链接 | 并发路径替换时可能把回收站/恢复内容写到 vault 外 | 1 | 已修复 |
| F-07 | 低 | Markdown 任务复选框白名单只检查前缀 | 伪造属性可能绕过渲染器的可信 HTML 分支 | 3 | 已修复 |
| D-01 | 高 | 基线 Go 1.25.0 标准库命中已公开的 Go vulnerability database 条目 | 网络、证书解析、URL 和资源处理路径存在已修复的标准库风险 | 4 | 已修复 |

- Vite 构建仍提示 `modal.ts`/`toast.ts` 同时被静态和动态导入；这是拆分机会，不影响正确性或安全边界，本轮不改变模块加载拓扑。

## 残余风险与非目标

- 更新元数据目前通过 HTTPS CDN 获取；本计划保留 SHA-256 校验和受限域名策略，但不引入新的签名密钥分发体系。
- vault 是用户主动选择的本地目录；对用户明确放入其中的普通文件不做内容防病毒扫描。
- 现有用户未提交的 `internal/store/trash.go` 改动和 UI 截图属于工作区已有内容，修复过程中保留并纳入测试验证。
